# CI/CDおよびリリース戦略 (CI/CD & Release Strategy) - Counail

本ドキュメントは、システム「Counail」における継続的インテグレーション（CI）、継続的デリバリー（CD）、およびリリース管理の運用方針を定義したものである。

---

## 1. リリース戦略 (Release Strategy)

開発効率と安全性を両立させるため、トランクベース開発に近い運用と自動化されたリリース管理を行う。

### 1-1. バージョン管理の方針
- **セマンティックバージョニング (Semantic Versioning 2.0.0)** を採用する。
  - 形式: `vX.Y.Z` (メジャー . マイナー . パッチ)
  - *X (メジャー)*: 後方互換性のないAPI変更または大幅な構造変更。
  - *Y (マイナー)*: 後方互換性のある機能追加（Goal Typeの追加、新しいAgentチームの追加など）。
  - *Z (パッチ)*: 後方互換性のあるバグ修正、微細な調整。

### 1-2. ブランチ戦略とリリースフロー
- 開発は機能ブランチ（`feature/` または `fix/`）で行い、プルリクエスト（PR）を作成する。
- 開発ブランチは、自動テストおよびレビュー通過後に `main` ブランチへマージされる。
- **`main` ブランチへのマージ** を契機として、CI/CDパイプラインを介して自動的にステージングおよび本番環境へのデプロイが実行される。

---

## 2. CI (継続的インテグレーション) 設計

品質の高いコードを維持し、結合時の手戻りを防ぐため、プルリクエストの作成・更新時に以下のCIジョブを自動実行する。

### 2-1. 静的解析およびLintチェック
- **Backend (Go)**: `golangci-lint` を実行し、スタイル警告、不要コードの検出、およびセキュリティリスクのチェックを行う。
- **Frontend (Next.js)**: `eslint` および `prettier` によるコードフォーマットチェックを実行する。

### 2-2. 自動テストの実行
- **単体テスト (Unit Test)**: すべてのパッケージにおける単体テストを実行し、テスト通過率100%をマージの必須条件とする。
- **統合テスト (Integration Test)**: DB（モックまたはローカル検証用コンテナ）やRedisを交えた統合シミュレーションを実行する。

---

## 3. CD (継続的デリバリー) 設計

本番環境および検証環境へのデプロイメントを安全かつ迅速に行うため、自動デプロイパイプラインを構築する。

### 3-1. デプロイプロセス
`main` ブランチへのマージ時、GitHub Actions（またはGCP Cloud Build）を用いて以下のCDパイプラインがトリガーされる。

```text
mainブランチへマージ
       │
       ▼
Dockerコンテナイメージのビルド (GCP Artifact Registryへプッシュ)
       │
       ▼
Google Cloud Run への自動デプロイメント
       │
       ▼
Supabase データベースマイグレーションの自動適用 (必要時のみ)
       │
       ▼
リリース完了通知 (Slack/GitHub Release等)
```

### 3-2. 環境の分離
- **Staging環境**: `main` ブランチに準じた動作確認用環境。APIキーやDB接続文字列は検証用を使用する。
- **Production環境**: エンドユーザー向け本番環境。高可用性および厳重なデータ隔離を適用する。
