# プロンプト設計原則

## 全 AI 共通

### 構造

すべての指示プロンプトは以下の構造を持つ:

1. **役割宣言** — 「あなたは AI 三位一体開発における○○です」
2. **入力** — 何を読むか（参照ドキュメント一覧）
3. **タスク** — 何をするか（具体的な手順）
4. **出力フォーマット** — 何を出すか（テンプレート）
5. **禁止事項 / 制約** — 何をしないか
6. **完了チェックリスト** — 自己検証項目

### IO フォーマット固定

LLM の安定性を上げるため、入出力を明示する:

```
Input:
- task.md
- constraints.md
- relevant ADR

Output:
- changed files
- summary
- blockers
```

### 「法律」と「今日の仕事」の分離

| 種別 | ファイル | 性質 |
|---|---|---|
| 法律（不変） | CLAUDE.md / GEMINI.md | プロジェクトを通じてほぼ変わらないルール |
| 今日の仕事（可変） | .context/current.md | 今からやる具体的な実装タスク |

## Task フォーマット

```
Goal:
Input:
Output:
Constraints:
```

## Linear Task 作成基準

- 1 Task = 0.5〜2 時間で完了できる単位
- 1 ファイル or 1 機能単位で分割
- テスト可能な単位で分割
- タイトル先頭に `[Phase X]` を付与
- 受け入れ条件（DoD）を必ず記載
